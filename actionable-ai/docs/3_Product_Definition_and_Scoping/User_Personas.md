# User Personas: Actionable AI (A²I) Platform

Understanding who we are building for is critical to designing intuitive workflows. For the A²I Platform, we have four distinct user personas representing different layers of interaction with the system.

---

## 1. The Integrator (Primary B2B Buyer)

**Name:** David, Lead Software Engineer  
**Demographics:** 30s, highly technical, works at a mid-market SaaS company.

**Goals:**
* Implement a support chatbot quickly without spending months building a custom LangChain/Agent architecture.
* Ensure absolute data security and prevent the AI from executing unauthorized backend actions.
* Avoid taking down the company's website due to heavy frontend bundle sizes.

**Pain Points:**
* Hates writing documentation when shipping new features.
* Frustrated by "no-code" tools that lack deep API integration capabilities.

**A²I Platform Use Case:**  
David uses our platform to manually upload his API documentation PDFs into the "Quick Start" sandbox to test the agent. Once he confirms it works, he grabs our lightweight JS widget script and registers a few internal API endpoints (like `refundUser()`) using our strict schema definitions. (He plans to automate the GitHub repository connection once the V1 update is released).

---

## 2. The Content Curator (Secondary B2B User)

**Name:** Sarah, Product Manager / Technical Writer  
**Demographics:** 20s-30s, tech-savvy but not a coder.

**Goals:**
* Ensure customer-facing documentation is accurate and easy to read.
* Identify gaps in the knowledge base by analyzing what customers are asking the bot.

**Pain Points:**
* Constantly chasing engineers to explain how a newly merged feature actually works.
* Worried that an AI might hallucinate and tell a customer something completely wrong.

**A²I Platform Use Case:**  
Sarah logs into the internal dashboard to review the "Draft" documentation automatically generated by the A²I system after David merged a PR. She edits the tone, approves the doc, and checks the Query Logs to see recent AI interactions.

---

## 3. The End-User (The Customer)

**Name:** Alex, SaaS Subscriber  
**Demographics:** Varies widely, standard SaaS end-user.

**Goals:**
* Get a problem solved or a question answered as quickly as possible without leaving the app.
* Complete tasks without having to read a 10-page manual.

**Pain Points:**
* Chatbots that just spit out generic links to help center articles.
* Chatbots that don't understand the context of the page they are currently on.

**A²I Platform Use Case:**  
Alex asks the floating widget "How do I upgrade to the Pro tier?". Instead of getting a link, the widget replies, "I can do that for you. Would you like me to upgrade your account to Pro for $20/month?" and provides a secure [Confirm Upgrade] button right in the chat.

---

## 4. The Internal Rep (The Staff Member)

**Name:** Marcus, Sales/Support Representative  
**Demographics:** 20s-40s, client-facing, high volume of requests.

**Goals:**
* Answer highly technical prospect questions accurately on sales calls.
* Resolve support tickets quickly without pinging the engineering team.

**Pain Points:**
* Searching through disorganized Confluence or Notion pages.
* Not knowing if a specific feature is live yet or still in development.

**A²I Platform Use Case:**  
Marcus uses the "Internal Chatbot" view on the A²I dashboard to ask, "Does our API support bulk user deletion yet?". The AI reads the latest technical docs generated from the codebase and gives Marcus an exact, up-to-date answer.
